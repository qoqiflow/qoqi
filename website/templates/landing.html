Why

A process that waits is usually taken apart by hand.

For a payment, a person, a webhook, a date. Nobody can read it from top to bottom any more, and the bugs live in the gaps. Qoqi Flow keeps it a program.

Taken apart

  • the line it is ata status column
  • its variablesa JSON field
  • its sleepa delayed job
  • its retriesa counter, and a cron
  • its crash recoverya sweeper

With Qoqi Flow

  • the line it is atthe line it is at
  • its variablesits variables
  • its sleepwait time.after(3.days())
  • its retriesa for loop
  • its crash recoverynothing to write

What it does

A language and a runtime, made for flows.

compile time

Checked when it compiles

A flow reaches the world only through a step fn. The compiler points at the call that reaches the network, a file or a database outside a step, with the path of calls that leads there.

 recovery

Frozen, not replayed

An instance is taken up from what was saved, not by running its history again. The code need not be deterministic, and a new version never re-runs an old history.

 exactly once

Steps run once

What a step returned is written before the flow goes on. One that may have half run is run again under the same key; one declared Settled<T> is never run twice.

 versions

New code under running instances

stage marks where an instance may move to new code, and flow.lock records its shape. A change without a migrate fn is flagged, and refused by the daemon.

 testing

Tests that crash on purpose

A trial runs on a clock of its own, so three days pass in a moment. everyCrash stops the process after each write, and requires the same ending every time.

A step declared by a queue has no body in the flow: the daemon hands it to your application, signed with the queue's secret, and keeps what it answers. The declaration says how long it may take, and which step undoes it.
